***REMOVED******REMOVED*** What PR ***REMOVED***5 delivers

A user-visible feedback + share loop on top of the persisted backend that PRs ***REMOVED***1-4 already shipped. Three deliverables:

1. **Persist toggle on analyze page** — opt user into saving the report (sets `persist=1` on the SSE call).
2. **Share / report-detail page** — readable URL `/report/share/<token>` that renders the 9-section report.
3. **Feedback buttons** — section-level 👍/👎 + overall 👍/👎, posting to the backend + emitting Plausible events.

***REMOVED******REMOVED*** 1. Persist toggle (existing analyze page)

***REMOVED******REMOVED******REMOVED*** Where

`web/frontend/analyze.html` and `web/frontend/js/analyze.js` (or the equivalent file driving the SSE consumer).

***REMOVED******REMOVED******REMOVED*** Behaviour

- Add a checkbox **"💾 Save & share this report"** near the submit button, defaulting to checked.
- When checked, append `&persist=1` to the SSE URL. When unchecked, omit (= persist=0, backward compat).
- Read `X-Anon-Id` from `localStorage.getItem('anonId')` (existing pattern from `flags.js`/`favorites.js`) and pass as a request header.

***REMOVED******REMOVED******REMOVED*** Event handling

In the existing SSE event-loop dispatcher, add one new case:

```js
case 'persisted': {
  // payload: {id, share_token, share_url, created_at, is_partial}
  state.persistedId = payload.id;
  state.shareUrl    = payload.share_url;
  state.isPartial   = payload.is_partial;
  renderShareBar(state);
  if (window.plausible) {
    plausible('Report Persisted', { props: { is_partial: payload.is_partial } });
  }
  break;
}
```

The `persisted` event ALWAYS arrives BEFORE `done` (per spec §3.3) — no need to wait.

***REMOVED******REMOVED******REMOVED*** Share bar UI

When `state.shareUrl` exists, show a sticky bar above the report:

```
┌─────────────────────────────────────────────────────────┐
│ 🔗 https://beta.structural.bytedance.city/report/share/…  📋 Copy  ↗ Open │
└─────────────────────────────────────────────────────────┘
```

If `state.isPartial === true`, dim the bar + tooltip "Report is incomplete — share with caution".

***REMOVED******REMOVED*** 3. Feedback buttons (per-section + overall)

***REMOVED******REMOVED******REMOVED*** Component

Per-section: small thumb-up / thumb-down icon group below each of the 9 section headings.

```
<div class="feedback" data-section="borrowable_insights">
  <button class="up"   aria-label="useful">👍</button>
  <button class="down" aria-label="not useful">👎</button>
</div>
```

***REMOVED******REMOVED******REMOVED*** Click handler

```js
async function vote(reportId, section, voteValue) {
  const r = await fetch(`/api/report/${reportId}/feedback`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'X-Anon-Id': localStorage.getItem('anonId') || '',
    },
    body: JSON.stringify({ section, vote: voteValue }),
  });
  if (!r.ok) {
    // Toast: "Vote not recorded — try again"
    return;
  }
  const { total_up, total_down } = await r.json();
  // Update DOM counters
  if (window.plausible) {
    plausible('Report Feedback', {
      props: {
        section: section || 'overall',
        vote: voteValue === 1 ? 'up' : 'down',
        is_partial: state.isPartial || false,
      },
    });
  }
  // Mark as "voted" UI state — clicking again upserts (backend dedupes).
}
```

***REMOVED******REMOVED******REMOVED*** UX

- Disabled state while in-flight (200-300ms typical).
- After vote, visually mark the button "active" but allow the OTHER direction click to flip (backend upserts, our P1 fix in session ***REMOVED***16 ensures this works correctly even for overall votes with `section=None`).
- No "thanks" toast — the visual state change is enough.

***REMOVED******REMOVED*** 4. Plausible events to wire (analytics)

| Event name | When | Props |
|---|---|---|
| `Report Persisted` | `persisted` SSE event arrives | `is_partial: bool` |
| `Report Feedback` | feedback POST returns 200 | `section: string`, `vote: 'up'|'down'`, `is_partial: bool` |
| `Report Share Clicked` | user clicks copy / open on the share bar | `via: 'copy'|'open'` |
| `Report Share Page Viewed` | `/report/share/{token}` loads & returns 200 | `referrer: 'direct'|'analyze'|'mine'|'other'` |
| `Report List Viewed` | `/api/reports/mine` returns | `count: int` |

Wire all of these conditionally (`if (window.plausible)`) since the script is opt-in.

***REMOVED******REMOVED*** 7. Risk + mitigation

| Risk | Mitigation |
|---|---|
| Persisting LLM output that contains user PII | LLM output goes through the same path it always has; backend doesn't add new attack surface. Persist toggle defaults checked but is easy to uncheck. |
| Share URL accidentally shared via screenshot | v1 trade-off; token is unguessable; v1.1 may add revoke. |
| Feedback button spam | Backend's existing rate-limiter (10/min anon, higher for tiers) covers this. |
| `is_partial=true` reports getting shared | Share bar dims + tooltip explains; backend doesn't block sharing. |
| Plausible events not firing if blocker installed | Acceptable; feedback DB row is the source of truth, Plausible is for funnel analysis only. |
