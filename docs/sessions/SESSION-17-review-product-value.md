# SESSION-17 · 发布前产品价值审查

> 2026-05-21 · 审查对象：https://beta.structural.bytedance.city/ · 性质：纯产品价值审查，未改代码。
> 视角：一个第一次来的目标用户（按 SESSION-13 定义，楔子人群 = 科普创作者 / 产品经理）。
> 方法：首屏 + start-here 实地走查 + 实测一份完整报告（`/api/analyze/stream`，b_id=soc-160，query=「月活每月掉 7% 怎么干预」，捕获前 6/9 段）+ 拒答门实测 + /reports 入口核查。

---

## 0. 一句话总评

**价值层面，现在还不值得对外正式发布——但差距不大，缺的是 3~4 件「硬」的东西，不是推倒重来。**

核心交付物（9 段报告）的质量**超出预期地扎实**，这是这个产品真正的底牌；但它被三层东西挡在用户面前：① 首屏承诺的是一个会被 Perplexity 碾压的「搜索引擎」，② 没有拒答门，问「1+1 等于几」也照样一本正经生成报告，③ 一份报告要等 3 分钟以上、全程没有任何时长预期管理。一个新用户大概率在「价值兑现」之前就走了。

定位是「beta」的产品可以带着瑕疵上线，但**「跨学科搜索引擎」这个对外说法本身就是发布前必须改掉的价值缺口**——它把产品摆到了一个打不赢的擂台上。

## 1. 价值承诺：清晰，但摆错了擂台

### 1.1 首屏说了什么

- 标题：「Structural — 跨学科搜索引擎」
- 副标题：「输入复杂问题，AI 从地震、神经、金融等领域为你找出结构相同的成熟解法」
- 4 个示例 chip（SVB 挤兑 / 月活衰减 / 谣言传播 / 团队相变）+ 3 张引导卡片（23 等价类 / 39 精选发现 / Phase Detector）

**「清不清晰」——清晰。** 一个新用户 60 秒内能 get 到「我输入一个问题，它去别的学科找解法」。示例 chip 和卡片可点，引导入口给得够。这一层做得不错。

**「真不真实 / 兑现没」——这里有结构性问题：**

| 问题 | 证据 | 后果 |
|---|---|---|
| **「搜索引擎」是错误的品类词** | 项目自己的 SESSION-13 写得很清楚：「它不是搜索引擎，是类比生成器」「召回严重依赖关键词重叠」。但首屏 4 处（title / meta description / og / tagline）全用「跨学科搜索引擎」 | 用户带着「搜索引擎」的预期进来——秒回、可信、确定性结果。实际拿到的是「3 分钟才出、LLM 在圆场、偶尔硬拗」的东西。**预期和现实的落差 = 差评和流失的最大来源**。而且「搜索引擎」这个词直接把产品摆到 Perplexity 的擂台上，那是必输的擂台。 |
| **「找出成熟解法」承诺过满** | 副标题说「找出结构相同的**成熟解法**」。实测「月活流失」配到的同构对象是「间隔重复记忆衰减」——这个匹配其实**很妙**，报告也真的给了 SM-2、SuperMemo 双参数模型当「可借用工具」 | 这一例兑现了。但产品没有 PASS/FAIL 判定暴露在用户面前（SESSION-13 明明把「敢说 FAIL」列为信任资产），用户无法判断「这次的类比是真的还是硬凑的」。承诺「成熟解法」却不标注置信度 = 把验证风险转嫁给用户。 |

**结论**：价值承诺的「文字清晰度」合格，「品类定位的真实性」不合格。SESSION-13 已经想清楚要从「找类比」挪到「验证+迁移」，但**首屏一个字都没改**——产品方向文档和对外门面是脱节的。

## 2. 首跑体验：会在「价值兑现」前流失

模拟一个产品经理第一次进来，输入「月活每月掉 7% 怎么干预」（这正是首屏 placeholder 和示例 chip 引导他做的事）：

| 时刻 | 体验 | 评价 |
|---|---|---|
| 0s | 看到搜索框 + 示例 chip + 引导卡片 | ✅ 友好。空搜索框**不孤单**——有 placeholder 示例、4 个可点 chip、3 张卡片。这一层比多数同类产品做得好。 |
| 点击提交后 0~180s+ | 前端有 loading 进度行「已生成 {chars} 字 · AI 正在写研究报告」 | ⚠️ **有进度反馈但没有预期管理**。首屏和等待页**全程没有一句「这份报告约需 3 分钟」**（grep 确认 index.html / ask*.js 里没有任何「秒/分钟/稍候」文案）。用户带着「搜索引擎」的秒回预期点下去，等到 30 秒就会觉得「卡了」并关掉。 |
| 实测 | 200 秒只跑完 9 段里的前 6 段，未到 `done` | 🔴 **完整报告 >3 分钟**，PRD M1.4 §5.1 自己也实测确认了这点。这是留存的绝对杀手。 |
| 边界场景 | 输入「1+1 等于几」 | 🔴 **系统照样生成报告**，把算术配给「间隔重复」，相似度 0.83 也硬上。**没有 out-of-scope 拒答门**。SESSION-13 把这列为头号硬伤，至今未修。 |

**关键判断**：首跑的「引导层」（chip / 卡片 / placeholder）做得不错，**但「兑现层」是破的**——慢 + 无预期管理 + 无拒答门。一个新人很可能在拿到那份其实很扎实的报告之前就已经离开。**「我想试试」的冲动有，但「试完觉得值」的体验没保障。**

## 3. 核心交付物质量：这是产品真正的底牌

实测「月活流失」这份报告（前 6 段：shared_structure / your_problem_breakdown / target_domain_intro / structural_mapping / borrowable_insights / how_to_combine），逐段评估：

**结论：是「真有用的洞察」，不是「看着唬人但空」。** 具体证据：

- **结构映射是真映射，不是修辞**：给出了 `MAU(t)=MAU₀·e^(-λt)` 对应记忆 `R=e^(-t/S)`，参数映射表逐项对齐（记忆稳定性 S ↔ 用户习惯强度、复习 ↔ 召回干预、可提取性 ↔ 用户活跃概率），每行还给了 `isomorphism_reason`。这正是 SESSION-13 说的「通用 LLM 给不了的：方程 + 变量映射表」。
- **可借用洞察是可执行的**：borrowable_insights 把 SM-2 算法的「答题质量动态调间隔」翻译成「按用户对召回干预的响应质量动态调召回间隔」，还给了「本周动作」（拉 60 天 Push 记录、算 EF 分布直方图、看是否双峰）。这是真能上手做的东西，不是空话。
- **有反直觉的真洞察**：「常规拉新无效，因为它增加 MAU₀ 但不改变 λ——把漏水的桶当成空桶」——这是一个 PM 真会「啊」一下的句子。
- **诚实**：how_to_combine 里有 `assumptions_to_verify`（怎么验证是不是指数衰减）和 `boundary_conditions`（月活 <1 万时统计规律失效，改用定性访谈）。**敢标边界条件，这是信任资产。**

**唯一遗憾**：这么好的交付物，被前面的延迟和定位问题挡住了，大部分用户根本到不了这一屏。**产品的问题不在「核心做得不够好」，在「好东西送不到用户面前」。**

> 注：未捕获到的后 3 段（risks_and_limits / citations / action_plan）。citations 段的真实性需另行核查（LLM 生成引文有编造风险）——见 §6 P1。

## 4. 留存钩子：基本没有

用户用完一次，有什么让他下周再来？**目前几乎没有。**

| 已有 | 状态 |
|---|---|
| `/reports`「我的报告」列表页 | 🔴 已建好，但**首页和导航全站无入口**（实测：首页 HTML grep 不到任何 `/reports` 链接）。等于没有。 |
| 收藏 | 导航有「我的收藏」，是个钩子，但偏轻。 |
| 分享链接 | M1.4 做了 share token。分享是**传播**钩子（拉新），不是**留存**钩子（自己回来）。 |
| 反馈 👍/👎 | M1.4 在收，但 SESSION-17 自己也承认「没人看这些数据」——对用户侧零感知，不构成回来的理由。 |

**缺失的留存设计**：
- 没有「报告→行动→结果」的回访闭环（SESSION-17 A3 提到过，未做）。一个 PM 拿了「本周动作」走了，产品不会再问「上周那条你试了吗」。
- 没有任何形式的「新内容订阅」——39 个精选发现是静态的，不会让人惦记。
- 报告是「一次性消费品」，用完即走。

**判断**：这是个「工具」而非「关系」。留存层面，发布前至少要让 `/reports` 入口可见 + 给一个最小的回访理由。

## 5. 定位清晰度：自己想清楚了，但没传达出来

**和 Perplexity / ChatGPT 的不可替代差异——SESSION-13 / SESSION-17 已经想得很透**：护城河是「验证过的同构对 + 能判 PASS/FAIL 的管线」，不是「类比生成」。一句话定位也写得很好：「别人卖『找到答案』，你卖『这个跨领域答案是真的、能搬过来，这是搬运清单』」。

**但这个想清楚的定位，在产品对外门面上一个字都没体现：**
- 首屏还是「搜索引擎」（= 和 Perplexity 同台 = 必输）。
- 没有 PASS/FAIL 判定露出（最强的差异化资产被藏起来了）。
- 没有「迁移清单」这个交付物概念——9 段报告里其实有 structural_mapping + how_to_combine，但没被命名、没被包装成「这是别人给不了你的东西」。

**判断**：定位的「内部清晰度」是 9 分，「对外传达清晰度」是 3 分。**发布前最便宜、最高杠杆的一件事，就是把已经想清楚的定位搬到首屏上。** 这不需要写代码，只需要改文案。

## 6. 发布前必须补的价值缺口（P0 / P1 / P2）

### P0 — 不补就不该对外发布

| # | 缺口 | 为什么是 P0 | 大致工作量 |
|---|---|---|---|
| **P0-1** | **改掉首屏定位文案**：「跨学科搜索引擎」→ 体现「验证 + 迁移」的说法（如「把你的难题，翻译成另一个学科已经解过的成熟模型」）。同步改 title / meta / og 4 处。 | 当前定位把产品摆到 Perplexity 擂台上必输，且和「3 分钟出报告」的实际体验严重不符 = 预期落差 = 流失/差评。纯文案改动，零代码风险，最高杠杆。 | 0.5 人天 |
| **P0-2** | **加 out-of-scope 拒答门**：低相似度 / 明显非「失控·级联·临界」类问题 → 不生成报告，给出「这个问题不在我擅长的范围，我擅长的是 X 类问题」+ 示例引导。 | 实测「1+1 等于几」照样硬拗成报告。一个会一本正经胡说的产品，留不住任何人，也会摧毁「敢说 FAIL」这个本该是核心信任资产的定位。 | 1~2 人天 |
| **P0-3** | **首跑预期管理**：报告生成前/中明确告知「这份深度报告约需 2~3 分钟，AI 正在逐段推演」。配合分段流式（现在已经是 SSE，前几段几十秒就能出）做「边等边读」。 | 完整报告 >3 分钟是既成事实，短期改不动（首 token 优化是另一条线）。但「无预期管理的 3 分钟」必流失，「有预期管理 + 边等边读的 3 分钟」可接受。这是用最低成本把延迟硬伤的伤害降到可发布水平。 | 1 人天 |

### P1 — 强烈建议发布前补，否则发布质量打折

| # | 缺口 | 为什么 |
|---|---|---|
| **P1-1** | **PASS/FAIL（或置信度）判定露出**：报告里把「这个类比有多可信」明确标给用户。 | SESSION-13 把「敢公开 FAIL」列为头号信任资产，现在完全没用上。承诺「成熟解法」却不标可信度 = 把验证风险甩给用户。这是和通用 LLM 最硬的差异点，藏着等于白有。 |
| **P1-2** | **/reports 入口可见** + 一个最小留存理由 | 留存钩子几乎为零。`/reports` 已建好却全站无入口，是「现成功能转化率为零」的纯浪费。顺手补。 |
| **P1-3** | **citations 段真实性核查** | LLM 生成的引文有编造风险（艾宾浩斯 1885、Wozniak SM-2 这些是真的，但不能假设全部都真）。对外发布前必须确认 citations 段不是幻觉，否则一旦被用户抓到编造文献，「验证型产品」的信誉直接崩。 |

### P2 — 发布后第一个迭代周期补

| # | 缺口 | 为什么 |
|---|---|---|
| **P2-1** | KB 扩到商业/组织母题 | 首屏 placeholder 写着「月活掉 7%」，但 KB 主体是统计物理。这次实测「月活↔间隔重复」碰巧匹配得好，但对「网络效应/飞轮/公地悲剧」类问题大概率硬凑。要让「产品经理」这群最该用它的人稳定命中，需要扩 KB。属于发布后重点，不卡发布。 |
| **P2-2** | 「报告→行动→结果」回访闭环 | 把产品从「一次性工具」变「持续关系」。也是拿到「类比到底有没有真帮上忙」这个最有价值反馈的唯一途径。 |
| **P2-3** | 「迁移清单」做成独立命名的交付物 | 9 段报告里的 mapping + how_to_combine 其实就是「迁移清单」，给它一个名字、一个可导出形态，是 B 端变现的抓手，也强化差异化。 |

## 7. 给用户的话（非技术总结）

这个产品的**核心引擎是好的**——我实测跑了一份「月活流失怎么干预」的报告，它把这个问题映射到「记忆遗忘曲线」，给的迁移建议（借用 SM-2 间隔重复算法来动态调召回节奏）是真能让一个产品经理「啊」一下、并且回去能动手做的东西。这不是唬人的空话，是真洞察。

但**这个好引擎现在被三件事挡在用户面前**：

1. **门面挂错招牌**——首屏写「跨学科搜索引擎」，会让用户拿它跟 Perplexity 比（比秒回、比确定性），那是必输的比法。你们自己的 SESSION-13 文档早就想清楚了真正的卖点是「验证 + 迁移清单」，但首屏一个字没改。**改文案，半天的事，是性价比最高的一件事。**
2. **会一本正经胡说**——问它「1+1 等于几」，它照样硬生成一份报告。一个验证型产品如果会硬拗，信任基础就没了。
3. **慢，而且不告诉用户要等多久**——一份报告要 3 分钟以上，全程没有一句「请稍候，约 3 分钟」。用户以为卡住了就走了，根本到不了那份好报告。

**所以「值不值得对外发布」——价值层面，现在不行，但离行不远。** 把 P0 的三件事补掉（改定位文案 + 加拒答门 + 加等待预期管理，合计约 3~4 人天），它就从「半成品」跨到了「一个有真实价值、可以挂 beta 对外的产品」。P1 再补上「可信度露出」和「/reports 入口」，发布质量就齐了。

一句话：**问题不在产品做得不够好，在好东西送不到用户面前。补的是「门面」和「兑现保障」，不是「重做核心」。**
