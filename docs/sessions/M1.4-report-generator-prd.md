## 0. TL;DR（3 句话）

`/api/analyze/stream` 已经是一个完整的 9-section 深度报告 SSE 流，**M1.4 不是写新的生成器**，而是把它**封装成持久化、可分享、可被反馈的 Report 资源**。Cross-judge 在 v1 阶段**先不接**（3× 延迟会破坏 UX，且 SSE 不是它的设计场景）；保留 v1.1 异步 critique pass 的接口扩展点。Report 持久化用现有的 history.db（SQLite），share URL 走签名 token，零基础设施新增。

## 1. 背景与目标

### 1.1 现状

| 维度 | 现状 |
|---|---|
| 报告 SSE 流 | `/api/analyze/stream` 已上线，9 个 section（shared_structure → action_plan） |
| 缓存 | `MappingCache`(JSONL) 按 `(query_hash, b_id, lang)` 存最新报告，重复 query 命中即播放 |
| 持久化 | ❌ 报告只存在 cache 文件里，无 DB 表，无 ID，无 share URL |
| 分享 | ❌ 用户无法生成 "把这份报告发给同事" 的链接 |
| 历史 | ✅ `history.db` 已存 ask 历史（不存 analyze） |
| 反馈 | ❌ 报告页无 "有用 / 无用" 反馈 |
| Cross-judge | ✅ 包就绪（`packages/cross-judge` v0.1.0），ask & analyze 均**未**调用 |

### 1.2 M1.4 要解决的具体问题

1. **不能分享**：用户看完一份高质量报告，无法把链接发给同事/客户。
2. **不能回看**：用户离开页面后，没有 "我之前看过的报告" 入口（除非命中 cache）。
3. **不能反馈**：我们不知道哪些报告用户觉得有用、哪些是垃圾——影响 ICP 验证 + 后续 prompt 调优。
4. **没有版本字段**：cache 命中的报告里没有 `(model, prompt_version, generated_at)`，未来回归测试无法定位 "这条差是哪个版本生成的"。

### 1.3 非目标（v1 明确不做）

- ❌ **不接 cross-judge 同步 critique**（会让 60s 报告变 3 分钟，UX 不能接受）
- ❌ **不做新的 LLM pipeline**（analyze.py 的 9-section 流已经够好）
- ❌ **不做 PDF 导出**（W7-D Pro 层第 2 月再做）
- ❌ **不做 multi-tenant 权限**（v1 = 公开可分享 / 私密只能持有 share token 的人访问）
- ❌ **不做 report comparison**（A vs B 两份报告对比是 v2）

## 2. 范围与用户故事

### 2.1 三个核心用户故事

**US1 — 持久化**
> Sarah（独立分析师）刚跑完一份 "为什么 SVB 倒闭的结构同构是 X" 的报告，关掉浏览器去开会。两小时后回来，想再看一遍——她应该能在 "我的报告历史" 里找到，不依赖 cache 是否还在。

**US2 — 分享**
> Sarah 觉得这份报告有意思，想发给同事 Mike。她点 "分享"，得到一个 URL `https://beta.structural.bytedance.city/report/r_<token>`，Mike 无需登录即可打开，看到一模一样的完整报告。

**US3 — 反馈**
> Mike 看完觉得 "borrowable_insights 这段没用、risks_and_limits 这段很到位"，他点 section 旁的 👍/👎 按钮，我们收到一条 `{report_id, section, vote, ts}` 反馈事件，进入 ICP 验证 / prompt 调优队列。

### 2.2 范围

| 模块 | v1 范围 | v1.1+ |
|---|---|---|
| Report 数据模型 | ✅ DB 表 + Pydantic schema | — |

## 3. 数据模型

### 3.1 DB schema（SQLite，新表）

```sql
-- web/backend/data/history.db 已存在，加新表
CREATE TABLE IF NOT EXISTS reports (
    id              TEXT PRIMARY KEY,           -- 'r_' + 16 hex chars
    share_token     TEXT UNIQUE NOT NULL,       -- HMAC-signed, 32 chars
    query           TEXT NOT NULL,              -- user's original text_a
    rewritten_query TEXT,                       -- LLM-rewritten (if any)
    b_id            TEXT NOT NULL,              -- KB target phenomenon id
    lang            TEXT NOT NULL,              -- 'zh' / 'en'
    payload         TEXT NOT NULL,              -- JSON: full 9-section report
    model           TEXT NOT NULL,              -- model used (e.g. 'deepseek/deepseek-chat:nitro')
    prompt_version  TEXT NOT NULL,              -- prompt schema version, e.g. 'v1'
    created_at      TEXT NOT NULL,              -- ISO-8601
    creator_anon_id TEXT,                       -- anonymous identifier (from X-Anon-Id)
    creator_tier    TEXT,                       -- 'anon' / 'free' / 'pro' / ...
    is_public       INTEGER NOT NULL DEFAULT 0, -- 0 = needs share_token, 1 = listed
    view_count      INTEGER NOT NULL DEFAULT 0,
    last_viewed_at  TEXT
);
CREATE INDEX idx_reports_anon ON reports(creator_anon_id, created_at DESC);
CREATE INDEX idx_reports_share_token ON reports(share_token);

CREATE TABLE IF NOT EXISTS report_feedback (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    report_id   TEXT NOT NULL REFERENCES reports(id) ON DELETE CASCADE,
    section     TEXT,                           -- which section, NULL = overall
    vote        INTEGER NOT NULL,               -- +1 / -1
    voter_anon  TEXT,                           -- anonymous voter id
    note        TEXT,                           -- optional free text (v1.1)
    created_at  TEXT NOT NULL
);
CREATE INDEX idx_feedback_report ON report_feedback(report_id);
```

### 3.2 Pydantic schema（`web/backend/schemas.py`）

```python
class ReportCreatedResponse(BaseModel):
    """POST /api/report — returned after SSE generation finishes + persist=true."""
    id: str                  # 'r_<16hex>'
    share_url: str           # full URL incl. token
    share_token: str
    created_at: str

class ReportDetailResponse(BaseModel):
    """GET /api/report/{id_or_token}."""
    id: str
    query: str
    rewritten_query: Optional[str]
    b_id: str
    lang: str
    payload: dict            # the 9-section dict
    model: str
    prompt_version: str
    created_at: str
    view_count: int

class ReportListItem(BaseModel):
    id: str
    query: str
    b_id: str
    created_at: str
    view_count: int

class ReportFeedbackRequest(BaseModel):
    section: Optional[str]   # one of the 9 section keys, or None for overall
    vote: int                # +1 or -1
    note: Optional[str] = None  # v1.1

class ReportFeedbackResponse(BaseModel):
    ok: bool
    total_up: int
    total_down: int
```

## 4. API 设计

### 4.1 endpoints

| Method | Path | 目的 | Auth |
|---|---|---|---|
| `GET`  | `/api/analyze/stream?persist=true&...` | SSE 流 + 完成后自动持久化（**复用现有 endpoint**） | 同 analyze |
| `GET`  | `/api/report/{id}` | 按 id 读已持久化报告（owner only） | anon-id match |
| `GET`  | `/api/report/share/{token}` | 按 share token 读报告（公开） | none |
| `GET`  | `/api/reports/mine` | 当前 anon 的历史列表（分页） | anon-id |
| `POST` | `/api/report/{id}/feedback` | section 级反馈 | none |
| `GET`  | `/report/{slug}` | 前端页面（SSR / static + JS fetch） | none |
| `DELETE` | `/api/report/{id}` | 删除自己的报告（v1.1） | anon-id match |

### 4.2 SSE 流升级（最小改动）

`/api/analyze/stream` 加 query param `persist=1`（默认 0，向后兼容）：

```
GET /api/analyze/stream?b_id=...&text_a=...&persist=1

事件流（不变 + 新增最后一个）：
  event: meta
  event: section (shared_structure)
  ...
  event: section (action_plan)
  event: done {report: {...}, from_cache: false}
  event: persisted {id: "r_abc123...", share_url: "https://.../report/r_abc123..."}  ← 新增
```

**为什么 persist 不默认 true**：避免给 cache 命中场景重复存盘（一份内容存两次），也给 dogfood / e2e 测试一个 "不写库" 的开关。

### 4.3 share_token 设计

- 格式：`HMAC-SHA256(report_id, SECRET)[:32]` → 32 hex chars
- SECRET：`STRUCTURAL_SHARE_TOKEN_SECRET` env，deploy 时注入（同其它 secrets）
- 验证：`GET /api/report/share/{token}` → 反查 `reports.share_token = ?`
- **不做**：token 不可 revoke（v1），不带过期（v1）。简单优先。

## 5. 关键技术决策

### 5.1 同步 vs 异步 — **答：同步**

`/api/analyze/stream` 平均完成时间 60-120s（user 已经在等 SSE），完成后**同步**插一条 row 到 SQLite 即可（< 5ms）。

**不引入 job queue**——Celery / RQ / dramatiq 都是 v1 不需要的复杂度。SQLite WAL 模式已开，单文件并发足够。

### 5.2 cost reservation — **答：不需要新机制**

报告生成的 LLM 成本（一次 deep_analysis 调用，~$0.01-0.03）已经在现有 rate-limit / tier 机制里管控。M1.4 只是把生成后的 JSON 存进 DB，**不增加 LLM 调用**。

唯一新增成本：DB row（< 50KB / report）。按月 1k 报告估算 < 50MB。可忽略。

### 5.3 cross-judge 集成 — **v1 暂不接**

| 选项 | 延迟 | 复杂度 | v1 决定 |
|---|---|---|---|
| 同步 ensemble（生成时 3 model 投票） | 3× 当前 60-120s = 3-6 分钟 | 高（需要并行 LLM） | ❌ |
| 异步 critique pass（报告存盘后台跑 critique） | 用户即时看报告，critique 几秒到几十秒后追加 | 中（需要 task queue / cron） | ❌ v1 不做，v1.1 候选 |
| 完全不接 | 当前 60-120s | 0 | ✅ v1 |

**v1.1 计划**：报告 row 加 `critique_status: pending/done/error` + `critique_payload: JSON | null`。后台 worker 用 cross-judge 跑一遍，把 `disagreement` / `agreement_pct` / `flagged_sections` 写回 row，前端报告页底部多一段 "其他模型的不同看法"。

### 5.4 分享语义 — **公开 by default，无强 ACL**

- v1：任何持有 share_token 的人都能看（类似 Google Doc "anyone with link"）
- 列表（`/reports/mine`）按 `creator_anon_id`（cookie / localStorage UUID）过滤
- **不做账户系统**——v1 不强依赖 auth（reuse 现有 `X-Anon-Id`）

### 5.5 报告 ID 设计

- 短可读：`r_` + `secrets.token_hex(8)` = 18 字符总长（含前缀）
- 不用 UUID（太长，URL 难看）
- 不用 incremental int（暴露规模）
- prefix `r_` 让 log grep 友好

## 9. 风险与缓解

| 风险 | 缓解 |
|---|---|
| share_token 泄漏 → 报告被未授权访问 | token = HMAC，预测困难；v1 接受（类似 Google Doc）；v1.1 加 revoke |
| 用户大量发垃圾报告刷 DB | rate-limit 已在（tier 默认 10/min）；persist=1 不放大调用 |
| `payload` 超大撑爆 SQLite row | 单 report < 50KB；SQLite single-row max 1GB，10× headroom |
| Cross-judge 用户期待落空 | 报告页加 "more perspectives coming soon" 提示（v1.1 真接入时去掉） |
| 反馈被恶意刷 | voter_anon 限速 + 同 (report_id, voter_anon, section) 唯一约束 → upsert |
