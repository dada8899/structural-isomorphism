## 测试中发现的产品级 Bug（独立于报告质量）

### Bug 1（严重 / 信任崩）：search 与 analyze 用不同的 query，导致 search 推荐的结果在 analyze 被拒

P2 第一次选了 search 排名第 2 的「中等收入陷阱」（search 给的 cosine = **0.798**）。
但 analyze 端先对用户问题做 LLM rewrite，再用 rewrite 后的文本算 embedding——
对同一个「中等收入陷阱」的 cosine 变成 **-0.25**，低于 scope guard 的 0.30 floor，
报告被直接拒绝（`out_of_scope / low_similarity`）。

- **现象**：用户在搜索页明明看到一个 0.80 高分的跨领域匹配，点进去却被告知「超出能力范围」。
- **根因**：search 用原始 query 算分，analyze 用 rewritten query 算分——两套打分口径不一致。
- **后果**：用户会觉得产品自相矛盾、不可信。这是首次体验的硬伤。
- **建议**：analyze 的 scope guard 要么用与 search 一致的原始 query 算 similarity，
  要么 search 结果页就用 analyze 口径预筛，不让「会被拒」的卡片出现在结果里。

### Bug 2（中 / 显示问题）：`meta.similarity` 数值非法

三份报告 meta 里的 similarity 分别是 **9.5 / 4.76 / 4.27**——cosine 不可能 > 1。
后端对 `svc._embeddings` 直接做 `np.dot` 但没归一化（search 端是归一化的）。
若前端把这个数字展示给用户（「结构相似度 9.5」），属于明显穿帮。需统一归一化。

## P1 — 增长 PM｜D2 留存 18%（源领域：磁滞损耗）

### 关键摘录

- **共享结构**：「滞回耗散结构（路径依赖的不可逆能量损耗）」。把留存问题重构为
  「软磁材料被当成硬磁材料用」——82% 用户首次磁化后完全退磁。
- **问题拆解（why_stuck）**：「把留存问题当成激活问题来解，但实际上这是用户分层
  问题 + 产品-需求匹配问题。没有持续性需求的用户矫顽力本质为零，外力一撤立刻退磁，
  过度推送相当于反向磁化（直接卸载）。」
- **可借用工具**：斯坦因梅茨方程 `W_h = k_h·f·B_max^n`（1890）→ 迁移成
  「流失率 = 用户群属性 × 获客节奏 × 首次激活深度的幂次」，并给出用 SciPy curve_fit
  拟合 `k_h, n` 的具体做法 + `n>1.5` / `k_h<0.1` 的判断阈值。
- **本周行动**：5 条，前 3 条为诊断动作。Rank 1 = 拆分推送组/无推送组留存曲线
  （30 min，给了「推送组 22% vs 无推送组 9%」这种数字范例 + 验收标准）。

### 逐维度打分（满分 5）

| 维度 | 分 | 举证 |
|---|---|---|
| 可行动性 | **4.5** | 每条 action 有 how / verification / expected_impact / 估时 / 分类。Rank 1「按是否授权推送分两组算 D1/D2/D7/D30」是任何有埋点的团队当天能做的。没有正确的废话。 |
| 洞察深度 | **4.5** | 「软磁/硬磁用户」「矫顽力=0 的用户做留存优化是徒劳」「过度推送=反向磁化」——这是真换了个角度：把「优化漏斗」重构成「先分层、判断哪些用户根本不该优化」。这个 reframe 对一个卡在留存优化里的 PM 有实质价值。 |
| 可信度 | **4** | 斯坦因梅茨方程、瓦尔堡 1881、巴克豪森 1919、奈尔 1948 诺奖——这些史实真实准确。引用（Andrew Chen《Cold Start Problem》、Fogg 行为模型、ICWSM Jiang 2019）都是真书真论文。迁移公式 `R_D2 = k_h·A_first^n` 是类比构造（诚实标注为「方法论迁移」）。 |
| 迁移风险诚实度 | **5** | risks 段是全报告最强的部分：明确点出「平均留存率掩盖双峰分布」「工具类 App 一次性需求可能 60-80%、18% 可能已接近上限」「首次激活深度与留存可能是伪相关、因果反向」——并给每条配了验证方法（K-means 聚类 / 20 个定性访谈 / A/B 测试）。这是诚实的，没有硬吹类比。 |
| 首次体验 | **4** | 拿到报告瞬间是「有点东西」。「软磁材料被当硬磁用」这个标签让人记得住。 |

## P2 — 内容创作者｜小红书爆款不可复制（源领域：病毒扩散结构）

> 注：source 现象「病毒扩散结构」本身就是传播学，对一个做内容传播的创作者来说
> **几乎是同领域**，跨域感最弱的一份。但内容本身仍可用。

### 关键摘录

- **共享结构**：「幂律分布驱动的网络传播动力学」。把「数据忽高忽低」重构为
  「内容在传播阈值附近随机游走，你不知道阈值在哪、哪些变量在推它」。
- **why_stuck**：「模仿爆款失效，因为爆款是在特定时间窗口/竞争环境/用户情绪下越过
  阈值的，这些条件不可复制。在幂律网络里努力程度和传播结果几乎无线性关系。」
- **可借用工具**：① Berger 的 STEPPS 六维框架（把传播率从艺术变工程）；
  ② Bass 扩散模型 `f(t)=(p+q·F(t))(1-F(t))`——用 `q/p` 判断内容是否有自传播能力，
  把「卡 3 万粉」诊断为「高 p 低 q」；③ Pastor-Satorras 无标度网络传播阈值。
- **本周行动**：5 条。建 25 行传播参数表 → Excel CORREL 找高杠杆变量 → 写发布前
  3 条检查清单 → 千瓜/新红找蓝海关键词 → 测分享触发器文案。

### 逐维度打分

| 维度 | 分 | 举证 |
|---|---|---|
| 可行动性 | **4.5** | 极具体：导出 60 天数据、手动标 4 列、CORREL 算相关系数、`|r|>0.3` 才算找到杠杆、`|r|<0.2` 就回去补 10 篇。连工具名（千瓜数据、新红）都点名了。这是能照着做的。 |
| 洞察深度 | **3** | Bass 模型的 `q/p` 诊断（「靠算法推 vs 靠自传播」）确实有价值。但整体偏弱：source 是传播学，对内容创作者不算「别的学科」；STEPPS 是内容营销圈众所周知的框架，不是「跨领域借来的新东西」。这份更像「一个懂传播学的资深顾问」，而非「结构同构带来的意外视角」。 |
| 可信度 | **4** | Berger《Contagious》2013、Bass 1969 Management Science、Pastor-Satorras & Vespignani 2001 PRL——引用全部真实准确。`R_0 = β·⟨k²⟩/⟨k⟩` 是 SIR-on-network 的标准公式，没编。 |
| 迁移风险诚实度 | **4.5** | risks 很诚实：「算法是黑箱且每季度变，收藏率权重可能迁移到完播率」「STEPPS 基于美国数据、中国用户面子/圈子认同权重不同」「幸存者偏差：你只看得到成功的爆款」。该泼的冷水都泼了。 |
| 首次体验 | **3** | 「就这？」偏多。一个做了几年小红书的创作者，看到 STEPPS 和「加一句分享引导语」会觉得似曾相识。 |

## P3 — 创业者｜30 人公司效率塌陷（源领域：减速器效率级联）

### 关键摘录

- **共享结构**：「级联效率衰减（乘法损耗结构）」`η_total = ∏η_i = η^n`。
  「损耗是乘起来不是加起来——这就是为什么 10→30 人还好，30→50 突然什么都慢了。」
- **why_stuck**：**全报告最锋利的一句**——「你在优化节点，但应该优化拓扑。
  把每个人效率从 85% 提到 90%，对总效率的改善远不如把链路长度 L 减 1。」
- **可借用工具**：① 级联效率公式 → `L_max = ln(0.5)/ln(η)`，η=0.85 时 L_max≈4.3，
  超 4 跳的决策链执行质量低于 50%，并给了用任务对齐度反推 η 的方法；
  ② 并联传动路径 → Spotify Squad / 亚马逊两个披萨团队，把全连接串联改成并联自治小队。
- **本周行动**：5 条。画 10 个任务的沟通链路图 → 算公司的 L_max → 记录自己一周
  参与的决策并分「只有我能做/别人也能做」→ 暂停「协调型」岗位招聘 → 设计并联小团队试点。

### 逐维度打分

| 维度 | 分 | 举证 |
|---|---|---|
| 可行动性 | **4.5** | Rank 3「本周每天记录你参与的所有决策，标注『只有我能做/别人也能做』，把后者的决策标准写一句话发给负责人」——这是创始人下周一就能做、且直击放权痛点的动作。Rank 4「协调对象 >3 个团队的岗位暂停招聘」是一个具体的、有点反直觉的决策建议。 |
| 洞察深度 | **5** | 这份是三份里最强的。「优化节点 vs 优化拓扑」是真正的认知升级——大多数创始人卡在「招更好的人/开更高效的会」（优化节点），报告用乘法损耗结构论证了这条路边际收益极低，必须改拓扑。`L_max` 公式把「这个流程要不要重设计」从拍脑袋变成有数字标准。 |
| 可信度 | **4** | 乘法效率级联 `η^n` 是机械工程真实公式。Spotify Squad（Kniberg 2012）、亚马逊两个披萨团队（Bezos ~2002）真实。`L_max=ln(0.5)/ln(η)` 是自洽的类比构造，逻辑成立。「Shigley 1956」的最优级数公式略有拼装感，但方向正确。 |
| 迁移风险诚实度 | **5** | risks 段非常诚实且关键：「组织损耗来源多元（激励错位/文化冲突），乘法级联可能过度简化——若你的问题主因是销售和产品目标不一致，拓扑优化效果有限」「并联拆分会破坏需要全局视角的业务」**「创始人本人就是最大的串联瓶颈节点，但改变它有文化阻力，不真放权所有拓扑重设计都会退化回老样子」**——最后这条直接戳穿了方案能否落地的真正命门，没有回避。 |
| 首次体验 | **4.5** | 「优化拓扑不是优化节点」+「你自己是最低效的那一级齿轮」——拿到瞬间是「哇」。 |

## 对比通用 LLM：这个产品多给了什么？

把同样三个问题直接丢给 ChatGPT/Claude，会得到什么：

- **P2（内容创作者）**：通用 LLM 给的答案和本报告**高度重合**。STEPPS、Bass 模型、
  「加分享引导语」、「找蓝海关键词」——这些都是通用 LLM 问「小红书爆款怎么做」时
  的标准输出。本报告的增量约等于 0~10%。**P2 的产品价值基本是空的。**
- **P1（留存）/ P3（组织）**：通用 LLM 默认会给「同领域」答案——P1 会讲 Aha moment、
  onboarding、留存曲线分层；P3 会讲 Spotify、授权、OKR。它**不会主动**用「磁滞损耗」
  或「减速器效率级联」来重构问题。

**产品真正多给的东西，有 3 个，但都不稳定：**

1. **强制的 reframe（最大价值）**：把「留存优化」重构成「磁性材料分层」、把
   「组织管理」重构成「拓扑 vs 节点」。这个跨域类比给了一个**记得住、能改变行动
   优先级的心智模型**。通用 LLM 你不特意要求，它不会给。
2. **结构化的 9 段骨架**：把一个模糊问题强制拆成「结构→拆解→源领域→对照→工具→
   结合→风险→行动」。这个结构本身对「想清楚一个复杂问题」有脚手架价值。
3. **诚实的 risks 段**：明确告诉用户「这个类比哪里会失效」「你的问题可能根本不在
   这」。通用 LLM 默认报喜不报忧——这段是真实差异化，且三份都做得很好。

**但要诚实**：上面 1 和 2，一个会写 prompt 的人对通用 LLM 说「请用一个完全不同
学科的已验证结构来重新理解我这个问题，并给出迁移风险」，能拿到 70~80% 同等的东西。
产品的价值是**把这个高级 prompt 产品化、降低门槛、并配了知识库做 source 检索**——
这是真价值，但**不是不可替代的护城河**。

## 最关键结论：真实价值含量与最大缺口

**真实价值含量：中上，约 65/100。**

产品能稳定产出**结构完整、可执行、且诚实标注局限**的研究报告——这本身不容易，
质量明显高于「让通用 LLM 随便答一段」。最值钱的是**强制 reframe + 诚实的风险段**，
P1 和 P3 确实做到了「让用户换个角度、且知道这个角度的边界」。

**但有三个价值缺口，按严重程度排序：**

1. **跨域质量完全取决于用户/系统选对了哪个 source 现象——而选择环节是脆弱的。**
   P1（磁滞损耗）、P3（减速器）选到了真·跨领域现象 → 报告惊艳；
   P2 让搜索把同领域的「病毒扩散结构」排第一 → 报告平庸，约等于通用 LLM。
   产品没有机制保证用户拿到的是「跨域的那一份」而非「同域的那一份」。
   **这是最大缺口：产品的核心卖点（跨域洞察）是抽奖，不是必得。**

2. **search 与 analyze 打分口径不一致（Bug 1），会在首次体验直接制造「自相矛盾」**——
   用户点了一个搜索给 0.80 分的结果，却被 analyze 拒绝。新用户撞上一次就会流失。

3. **等待 4.5 分钟的成本 vs 回报不对称。** P1/P3 值这个等待；P2 不值。
   产品目前无法在生成前告诉用户「这一份大概率惊艳/大概率平庸」，
   用户是在不知道结果质量的情况下押注 4.5 分钟。

一句话：**这个产品对「问题确实能映射到一个遥远学科」的用户有真价值（P1/P3 那种），
对「问题本身就在某个成熟领域里」的用户价值接近于零（P2 那种）——而产品目前
分不清这两类用户，也保证不了把前者导向跨域、把后者劝退。**

## 3 条最能提升用户价值的建议

### 建议 1：把「选对 source 现象」从抽奖变成可控——优先推跨域、明确排同域
P2 的失败根因是搜索把同领域现象排到了第一。应该：
- 搜索结果按「与用户问题的领域距离」加权排序，**同领域现象降权或单独分组**
（标「同领域参考」），把真正跨域的现象顶到最显眼位置；
- 生成报告前给用户一个一句话预览：「将用【机械工程·减速器】重新理解你的
【组织管理】问题」——让用户在花 4.5 分钟前就知道这次是不是真跨域；
- 若 top 结果全是同领域，直接提示用户「你的问题已经在成熟领域里，
建议直接查该领域方法」——诚实劝退，比硬产一份平庸报告更保护信任。

### 建议 2：修复 search/analyze 打分口径不一致（Bug 1 + Bug 2）
- analyze 的 scope guard 用与 search **一致的 query 形式**算 similarity，
或反过来让 search 用 analyze 口径预筛——绝不能让「搜索推荐的结果被分析拒绝」；
- 统一对 embedding 做归一化，杜绝 similarity > 1 的非法值流到前端。
这两个是信任级 bug，必须在公开前修掉。

### 建议 3：把「迁移风险段」提到产品的显著位置，作为差异化主打
三份报告里 risks 段是**最稳定、最难被通用 LLM 复制**的部分（通用 LLM 默认报喜）。
但它现在排在第 8 段，用户很可能没耐心看到。建议：
- 把「这个类比在什么条件下会失效」做成报告顶部的醒目模块，
甚至和「共享结构」并列；
- 在「本周行动」里，把 risks 中的验证动作（如 P1 的「先做 K-means 看是否双峰」）
显式前置为 Rank 0——先验证类比成立，再执行迁移。
这能把产品从「给你一个酷类比」升级为「给你一个**经过自检的**酷类比」，
后者才是通用 LLM 给不了的真护城河。
