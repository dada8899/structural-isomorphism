# Structural Isomorphism 总需求与完成标准

> 日期：2026-07-12
> 状态：执行中
> 权威边界：产品目标与验收合同；运行状态仍以 `NEXT_SESSION.md` 最新章节为准。

## 1. 总目标

把 Structural Isomorphism 建成成熟、可信、易懂的 AI for Science 产品与研究引擎。它不只检索跨领域相似现象，还要帮助用户形成结构假设、寻找反证、设计可区分实验、回写结果，并用严格证据证明这套方法比现有科研工作流更有用。

完成不是主观“看起来不错”。功能、体验、价值、用户动线、科学可信度和工程可靠性必须分别通过明确门禁；任一关键维度低于 90 分，整体不得称为完成。

## 2. 产品与功能

1. 重新审计并完善自然语言知识库、精选发现、实证验证、工作台、Phase Detector、报告、收藏、账户和研究页面。
2. 主动线固定为：问题输入 → 处理状态 → 结构指纹确认 → 候选比较 → 证据/反证/边界 → 最小实验 → 结果回写 → 下一步行动。
3. 每一步必须有成功、空状态、错误、超时、恢复和撤销路径，不允许静默失败或假成功。
4. 注册用户拥有跨设备收藏和后续研究资产；继续建设报告、实验、结果、导出与删除等账户资产闭环。
5. 论文能力采用 evidence-bound drafting：句子级 claim-evidence 绑定、引用和数值定位、负结果保留、投稿门禁；不得做不可审计的“一键投稿论文”。
6. 所有按钮、链接、表单、筛选、键盘操作和深路由都必须真实可用并纳入自动化检查。

## 3. 体验、设计与文案

1. 对标 OpenAI、Apple、Bear、Notion 和飞书的克制、清晰、优雅和反馈质量，不复制视觉表皮。
2. 桌面与 375/390/430 移动端覆盖完整旅程；保证触控目标、键盘、焦点、读屏、对比度、响应式布局和性能。
3. 每个功能按输入、等待、解释、结果、下一步、失败恢复六阶段评分，严苛目标均为 90 分以上。
4. 全站文案重新审校：先说用户能做什么和证据意味着什么，再渐进披露术语；减少黑话、缩写、绝对化和无法证明的价值表述。
5. 视觉系统、组件状态、间距、字体、图表、空状态和错误提示保持跨站一致。

## 4. 价值验证与用户模拟

1. 在真实用户研究前，用多角色模拟任务覆盖研究员、产品经理、增长负责人、博士生、跨学科科学家、新用户和怀疑者。
2. 使用至少两个异构模型家族独立评分；不同温度或同一供应商模型不算异构。
3. 评分必须引用页面、响应或证据定位，并同时记录正面价值、失败点、适用边界和评分方差。
4. 最终仍需 15–20 个真实研究密集型任务验证候选接受率、实验启动率、结果回写率、术语理解和 Weekly Verified Transfer Outcomes；模拟不能替代真人证据。

## 5. AI for Science 新范式

引擎闭环：

`科学问题 → 结构表示 → 跨域机制检索 → 可证伪假设 → 反例与边界 → 可区分实验 → 前瞻预测 → 结果回写 → 可信度更新`

必须证明的不是“模型能生成有趣类比”，而是以下至少一项可重复成立：

1. 比文献搜索、普通 RAG、单模型研究助手或不使用结构同构的消融版本更早发现有效机制。
2. 在相同成本下产生更多新颖、可证伪且被后续证实的假设。
3. 更快发现反证或错误迁移，减少无效实验。
4. 降低从问题到可执行实验的时间或成本，同时不降低科学真实性。

证据阶梯：历史盲测与泄漏防护 → 基线/消融/负对照 → 多人盲评与领域外推 → 预注册前瞻验证 → 独立复现。未达到相应等级时，产品和论文 claim 必须自动降级。

## 6. 深度发现研究

1. 所有同构候选按新颖性、机制可信度、可证伪性、潜在影响、验证成本、跨域迁移价值和伦理风险排序。
2. 高价值或可能改变行业的发现进入独立 dossier：已有知识、结构映射、竞争解释、关键反例、可区分预测、最小验证、复现材料和停止条件。
3. 不限定研究深度；只要边际证据仍能显著改变判断，就继续深入。
4. 不用案例数量代替质量，不把同方程、相关性或事后解释直接称为共同机制。

## 7. 数据、实验与研究治理

1. 逐项复核数据来源、许可、版本、校验和、schema、缺失值、泄漏、代表性与可复现命令。
2. 对过期、合成占比过高、来源不清或与当前 claim 不匹配的数据重新获取或降级。
3. 需要重跑的实验必须预先冻结问题、指标、基线、随机种子、失败条件和输出 manifest。
4. LLM 输出进入执行或科研结论路径时强制 schema、allow-list、边界检查、证据定位和人工/程序门禁。
5. 保留负结果、拒绝、冲突和不确定性；禁止挑选性汇报。

## 8. 工程、测试与交付纪律

1. 每个版本：规划 → Builder → 独立 Validator → 目标测试 → 全量测试 → CI/性能 → 部署 → 生产 smoke。
2. 关键功能必须有单元、边界、集成、浏览器和生产不变量测试；外部 API、数据库和文件 IO 必须有结构化错误日志。
3. 性能、无障碍、类型、覆盖率、检索质量、研究 claim 和生产健康全部 fail closed，不通过放宽预算或隐藏内容制造绿色。
4. 保持密钥只在私有 secrets 中；生产数据位于 Git 外；所有部署可回滚。
5. 多 Agent 仅并行边界清晰的审查、实现和验证；同一文件避免并发编辑，核心改动遵循 Builder-Validator。
6. `NEXT_SESSION.md` 是唯一接力入口；上下文接近 90% 时主动追加，compact 后先完整重读再继续。

### 8.1 跨 Session 可恢复性门禁

1. 不把聊天历史、模型记忆或摘要当作项目事实；代码仓、权威 manifest、CI、生产探针和 `NEXT_SESSION.md` 才是可核验事实源。
2. 每次交接必须追加而非改写历史，至少记录：当前 SHA 与分支、远端差异、完整工作树、未提交文件归属、Agent 状态、测试命令与结果、CI/部署编号、生产验证、数据与模型指纹、回滚位置、阻塞项和严格下一步。
3. 任何“通过”“已部署”“已完成”必须附可复核证据；运行中、仅本地通过、仅 HTTP 200、仅页面可打开均不得写成完成。
4. 新 Session 或 compact 后的第一组动作固定为：完整读取 `NEXT_SESSION.md` → `pwd`/repo/README 归档检查 → `git status`/`git log` → 检查 Agent 与 CI/生产漂移 → 才能修改代码。
5. 多 Agent 产物必须标注 Builder/Validator、文件边界和是否提交；主 Agent 独立复核后才可集成。
6. 上下文接近 80% 时开始整理证据，最迟在 90% 前完成追加；不得等自动截断后补写。
7. 每个可部署版本完成后立即更新交接，不把多个版本的状态攒到会话末尾。
8. 交接文件不得记录密钥、token、cookie 或私人账号值，只记录变量名、私有路径和轮换状态。
9. 自动驾驶期间主动同步阶段进展，不等待用户追问。至少在以下节点汇报：方案定稿、独立 Validator 结论、发现 P0/P1、目标测试通过、全量 CI 终态、部署完成、生产 smoke 终态和研究门禁升降级。
10. 每次主动汇报固定区分：已验证完成、正在运行、新发现问题、风险/不可自动完成边界、下一阶段；不得用“基本完成”掩盖运行中或未验证状态。

## 9. 完成定义

只有同时满足以下条件才可宣称项目完成：

- 核心用户旅程六阶段评分均 ≥90，且不存在 P0/P1 未解决问题。
- 每个公开页面和可见控件通过桌面、移动、键盘、无障碍和失败恢复验收。
- 功能、体验、文案、视觉、价值与科学可信度均有独立审查证据。
- 账户资产闭环、数据权利和安全边界真实可用。
- 至少一个核心科学发现通过预注册前瞻验证或独立复现；否则只能称为研究预览，不能宣称新范式已被证明。
- 全量测试、CI、性能、部署和生产 smoke 全绿，交接与复现材料完整。

## 10. 项目完成后的独立研究项

Structural Isomorphism 达到本文件完成定义后，再启动“真正无人值守的 Codex 自动驾驶控制面”研究。当前项目期间不扩张该基础设施范围，继续使用会话内自动执行、Agent 并行、CI、VPS 长任务和 `NEXT_SESSION.md` 续航。

后续研究至少覆盖：常驻 orchestrator、持久任务队列、自动续回合、阶段状态机、预算与权限边界、失败隔离、Builder-Validator 调度、CI/部署门禁、生产监控、跨 Session 恢复、人工升级条件和可审计停止机制。验收目标是用户离线时系统仍能安全推进并在阶段节点主动留档，而不是只让单个长进程持续运行。
