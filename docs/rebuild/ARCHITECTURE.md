# Structure 渐进改造架构

日期：2026-10-16。状态：规划候选，待产品规格和独立架构审阅。代码基线为 `13743b685d77b65a94a50c5a976b4bec9fa09610`。本文由 Architecture 单写，不代表共享代码契约已冻结或产品已开发就绪。

**保留现有 FastAPI 主产品、静态前端、账户与发布体系，先把研究对象、证据、执行状态和费用边界统一，再分批拆开职责。** 三项能力使用同一份研究记录，不建设三个各自存储、调用模型和定义证据的产品。现阶段保持单仓，Phase 与历史科研退出主任务的必要依赖，但是否保留公开入口由产品兼容清单决定。

## 1 用户流程和现有缺口

用户从一个现象、公式或研究问题进入；系统先记录事实、目标和未知，再给出候选、对应条件和证据。用户选中值得追查的候选后创建研究任务，查文献、检查数学关系、执行受限分析，得到结果和下一步验证；保存后可再次打开、继续或停止。

| 用户能力 | 可复用实现 | 尚缺的真实能力 |
| --- | --- | --- |
| 现象到跨领域解题 | `search_service.py` 的关键词/向量检索；`research_fingerprint.py` 的确认结构；`search_synthesis.py` 的候选白名单；`api/mapping.py` 的候选映射 | 模型与成熟方法的独立知识记录、原文支持、迁移条件检查、针对当前现象的可观察验证 |
| 公式对应 | `schemas.py` 的候选映射；`discovery_contract.py` 的候选公式和变量映射 | 有限公式语法、可检查变换、单位及假设、边界/初值比较、确定计算与不成立反例 |
| 真实深度研究 | `deep_report.py` 的结构和来源绑定；`api/analyze.py` 的校验后发布；`report_store.py` 的保存和回访 | 外部来源检索与原文读取、可追溯证据摘录、可恢复任务、执行记录及预算预留 |

`deep_report.py` 当前把来源限定为 `internal_kb`，`literature_status` 为 `not_checked`，`suggested_references` 最大长度为零；这是诚实的现有边界，不是外部研究已经可用。其 `generation_status="validated"` 只表示通过当前格式和语义约束，不等于数学或科学结论已验证。新结构必须显式区分这些含义，不能放宽旧校验后把同一报告改名为“深度研究”。

## 2 渐进职责边界

第一轮不换整套前端、不搬目录、不引入独立微服务平台。先在现有后端建立下列私有模块边界；实际文件路径由 Bootstrap owner 根据独立审阅后的契约一次确定。

| 边界 | 负责的决定 | 不承担的职责 |
| --- | --- | --- |
| Research API 与体验适配 | 输入、身份、状态投影、用户操作和错误反馈 | 不直接调用供应商、不自行升级证据 |
| Research Core | 研究对象、主张、候选、证据关联、状态不变量 | 不保存密钥、不执行模型生成代码 |
| Retrieval | 内部候选检索、外部来源发现及排序 | 相似度不转换为机制概率或证明 |
| Formula Check | 有限模型的规范化、变换与计算检查 | 不承诺任意公式自动证明，不推断自然语言变量确实相同 |
| Evidence | 来源获取、版本、位置、摘录、主张支持与冲突 | 来源存在不自动等于支持某主张 |
| Research Runner | 固定步骤调度、检查点、取消、重试和恢复 | 不让 LLM 自行选择任意网络、Shell、SQL 或权限 |
| Persistence 与 Budget | 所有权、事务、任务事件、费用预留/结算/对账 | 不把单进程内存计数当项目余额 |
| Operations | 确定版本、物料、发布、探测、恢复 | 不把服务进程存在当真实任务成功 |

`main.py` 当前仍包含大量 Phase 路由；静态页面、账户与研究功能也共用入口。拆分先抽应用服务并保留旧路由适配，再迁移页面消费者。只有引用归零、兼容验收通过后才删除旧适配。新的正式契约不由页面内部字段或旧缓存格式反向决定。

## 3 共同对象与证据边界

以下为共享契约必须定义的内容清单，**不是已冻结字段表**：

| 对象 | 必须保存的内容与不变量 |
| --- | --- |
| Phenomenon / Problem | 原始描述、观察事实、用户目标、变量/约束/未知、修订号；系统补充不得覆盖用户原始输入 |
| Model / Formula | 模型家族、符号及单位、方程树、参数域、假设、初值/边界、来源版本；表达合法与适用成立分开 |
| Method / Transfer | 来源领域已有方法、支持来源、变量映射、必要变换、可迁移部分、失效条件和待测预测 |
| Claim / Evidence | 主张 ID、来源版本/位置、支持/反对/不足、读取时间、内容摘要及哈希；每条支持关系可追溯到已取回内容 |
| ResearchTask / Step | 所有者、输入修订、允许步骤、状态、attempt、幂等键、资源上限、检查点和事件；重试不覆盖前一次事实 |
| CheckResult | 检查类型、输入/工具/参数版本、实际执行与输出摘要、通过/失败/未知/不支持；有限数值通过不能标一般数学等价 |
| ReportSnapshot | 输入修订、候选、证据与检查引用、报告版本、证据边界、部分/完成状态；旧快照保持原时点含义 |
| BudgetReservation | provider/account/currency、额度依据与核对时间、最坏费用、预留、实际消耗、未知费用和结算收据；所有消费者共用 |

建议将展示分为四个独立维度：检索相关性、数学检查状态、来源支持状态、目标现象验证状态。禁止将它们压成一个“可信度百分比”。候选、已知关系、经特定检查、实际目标验证分别用明确状态表达；格式正确、LLM 多数票和统计拟合也不能相互替代。

## 4 三项能力如何接线

### 4.1 现象解题

复用范围拒绝、结构确认和检索，新增模型/方法记录作为候选依据。输出至少包含两个可比较解释或明确说明为何只有一个候选；“没有可靠匹配”是合法结果。用户确认结构后生成新的输入修订，检索和报告必须绑定修订，不能静默沿用旧结果。

先从有限且有出处的模型家族开始。模型选择需检查观察是否支持其关键条件；成熟解法需区分原领域证据和目标领域迁移假设。行动建议指向可测量变量、干预或实验，并提供竞争解释及停止条件。自然语言中的“像”不触发自动干预。

### 4.2 公式对应

首版支持明确列出的表达式、关系与变换。服务端以有限语法解析成数据结构，限制长度、运算符、变量数和计算资源，不执行模型提供的 Python、Shell、插件或任意表达式。先检查变量/单位、参数域、假设、初边值，再做允许的符号或数值对照。

B1 必须在正式契约中分别枚举“排队与流量”“线性一阶储存与耗散”“局部稳定性与恢复速度”三类模型允许的表达式节点、运算符、变量/单位、参数域、变换步骤及检查种类，并明确解析长度/深度、数值规模、运行时间和内存上限。不得只写“有限语法”后交由模型临时决定；未列入允许范围的表达式、变换和资源请求一律返回不支持或越界。枚举表、消费者探针与产品展示绑定同一 contract revision，本轮文档不冒充该枚举已实现。

确定检查只产生其范围内的结果。例如规范化后的同一方程形式可以支持“形式一致”；要称特定模型等价，还要证明采用的映射与变换满足所声明条件。抽样轨迹接近只支持该参数和输入下的数值一致。对不支持的关系输出“未检查/不支持”，不能回退成模型自述证明。

用户应同时看到原式、标准式、变量对应、变换步骤、适用条件、反例和来源。自然语言概念到符号的选择仍可能是待验证假设；计算器不能为错误变量映射背书。

### 4.3 外部深度研究

来源发现和原文获取分开：搜索命中先形成候选来源，成功取回可定位原文后才成为可引用证据。记录题名、作者/机构（有则记录）、URL/标识符、发布日期、读取时间、位置、内容摘要和使用许可边界；获取失败、缺全文和来源冲突显式保留。

外部读取由服务器批准的连接器执行，限制 URL 协议、目标、重定向、响应大小、类型和超时；拒绝私网/本机、云元数据及非授权文件路径，重定向每跳复核。外部文献和模型输出都是数据，不能改变系统提示、调用范围、预算或账户权限。检索词先做隐私最小化，不把用户私有记录自动发送给外部服务。

研究任务执行固定步骤：问题版本 → 检索计划 → 来源取回 → 主张证据对照 → 可选确定分析 → 综合报告。报告必须有已完成、未完成和矛盾证据；不能把检索无结果等同于“世界上没有该研究”，也不能据未穷尽检索宣称原创。

## 5 持久化、取消与费用

复用现有 SQLite 经验和 `ClosingConnection`，首版可以继续单机部署。将新任务、步骤、证据快照和预算记录放入明确的持久数据根，代码切换不覆盖数据库。不要把现有多库“整理”成一次无验证的大迁移；先建立适配和迁移版本，验证备份恢复后再逐库调整。

任务建议状态：待执行、执行中、等待外部、取消请求中、已取消、失败、需对账、完成。每步以事务保存开始记录和 attempt，再调用外部服务，取得结果后保存收据和检查点。任务终态与报告完成度分开。连接中断不自动视为用户取消；进程恢复后先对账执行中的步骤，不能盲重试付费动作。

B1 同时冻结三层状态的显式映射：用户产品态（待执行、取证中、分析中、整理中、完成、证据不足、失败、已取消）、任务/步骤执行态、证据完成度。映射须覆盖等待外部、取消请求、回执未知、恢复和来源冲突，明确唯一投影规则及用户下一动作；不能由前端看到某步成功就自行标记研究完成。执行结束可以对应证据不足，需对账时不能展示完整成功，取消后已有证据的保留与可见性仍服从有效权限。正式枚举和映射由共享 owner 在 B1 与产品负责人核对后确定。

取消先阻止后续步骤，向在途请求发取消信号并记录结果；上游可能已计费，不能承诺取消即撤销费用。重复点击、刷新、后台重启和 worker 竞争都需要实际幂等检查。首版不靠聊天消息、STATUS 或本地锁字段声称可靠后台执行。

费用是第一条新共享边界。`cost_ledger.py` 当前只在进程内按 UTC 日计请求；`guarded-llm` 的 `Budget.consume` 在 provider 返回后执行，且网页后端未见其实际导入，因此两者都不能直接承担调用前的项目硬预算。复用其解析/重试思想，新增统一持久账本：

1. 核已充值账户、可用余额、币种、计价版本、自动充值/后付费状态与共享账户的外部消耗影响。
2. 以单一事务预留本次最坏费用；并发消费者和重试使用同一账本，额度不足不发请求。
3. 调用返回后按实际用量结算差额；未知结果保留预留，进入对账，不能自动释放再重试。
4. 在 provider 账户侧设置可用的硬限制；无法限制或估算供应商隐藏调用/工具成本时，停止该计费路径而不是承诺绝不超支。

预算接口与真实供应商余额能力尚需 DevOps/执行器实测；本文未调用付费 API。首版先限制可控的供应商/模型与输出上限，禁止模型自主切换其他收费服务。

## 6 安全、兼容与部署

复用现有账户、报告认领、私有导航与 `account_data_registry.py` 的导出/删除登记。每个新增研究任务、证据与快照均有 owner；外部素材不因公开可读就允许访问其他用户的研究上下文。账户删除要覆盖新表、缓存、分享状态与外部数据保留边界。补偿机制不等于跨库事务，需失败注入验证。

研究在途时发生账户删除、撤权或匿名记录认领变化，执行者必须在每步开始、对外发送及结果提交前重新核对当前 owner、授权有效性和删除/撤权版本；提交以同一持久化条件拒绝已失效的旧 attempt。不能只在任务创建时检查一次，也不能让迟到回执重新创建已删除的私有任务、报告或证据。身份改变后的结果投影、缓存和分享均重新检查访问；在途调用费用继续按最小必要收据对账，不为结算重建已删研究内容或泄露原用户数据。具体并发原语与留存字段由 B1 正式契约及失败探针验证。

PR #247 的匿名报告列表修复应作为安全基线候选优先吸收，经当前差异独审和测试后进入正式基线。其监测身份绑定与首装补丁另按部署目标验证。不要因其历史测试通过而跳过新组合的门禁。PR #246/#229 及其与当前代码的关系由 PMO 依据实际 diff 决定，不按编号顺序合并。

现有 `make verify-release` 已覆盖核心、后端、包、API/类型产物、浏览器和 Phase 构建；复用并补新消费者检查，不重建只验证空模板的假绿 CI。现有自动发布监听 main 的产品、账户和部署路径，合并前必须确认实际目标与发布门禁；文档规划 PR 与源码发布分别判断。

部署继续使用现有确定版本和物料校验机制。扩充 readiness 为真实读写/恢复及受控研究链检查；现有 health 的目录存在与环境变量存在仅是弱信号。任务状态和余额不进公开健康响应；线上探测不泄露问题、邮件、分享 token 或原文。

## 7 共享冻结前的最小风险探针

下表均为待执行，不能按本文存在标记通过。先验证会改变架构选择的风险，再细分开发。

| 探针 | 真实消费者与合法对照 | 必须失败或保持未知的反例 |
| --- | --- | --- |
| FormulaCheck | 三模型家族按正式允许表分别输入 → 对应检查 → 保存 → 页面投影 | 未枚举表达式/变换、单位错误、参数域不符、不同边界、超大/恶意表达式及资源超限；数值相似不得提升到一般证明 |
| Evidence | 实际取回一手来源 → 精确位置与主张绑定 → 保存重开 | 摘要不支持主张、伪引用、重定向到私网、无全文、互相矛盾来源 |
| Budget | 两个真实调用消费者并发预留/结算同一账本，重启仍保持额度 | 超额、重复幂等键、请求超时结果未知、已收费但回执丢失、外部账户消耗 |
| Runner | 创建 → 分步执行 → 检查点 → 进程中断 → 恢复 → 报告，另覆盖取消 | 两个 worker 抢同一步、旧 attempt 迟到、重复扣费/重复生成、取消后继续推进 |
| Ownership | 匿名/账户保存、认领、导出、删除与重开 | 原匿名列表继续看到已认领记录、跨账户读取、新表漏删、分享令牌进入日志 |
| In-flight Authorization | 在研究步骤发送前、返回后提交前分别触发账户删除/撤权/认领；有效 owner 的正常完成作合法对照 | 旧 attempt 继续外发、迟到提交重建已删资产、认领后匿名读取或分享泄露；费用未知必须保持对账，不以数据已删释放预算 |
| State Projection | 正式导出执行状态与证据记录 → 持久化 → 用户产品态 → 重开/恢复后再次投影 | 单步成功变成研究完成、回执未知显示完整成功、证据不足被隐藏、取消或撤权后仍显示无权内容 |

共享冻结需每类真实消费者使用正式导出完成生命周期，绑定完整 SHA、接口 revision 与独审；mock 形状合法不足以冻结。自然语言映射质量、来源支持和公式正确性另有独立领域验收，不由软件测试替代。

## 8 开发拆分与单写者建议

| 批次/owner | 主要范围 | 依赖与交付 |
| --- | --- | --- |
| Bootstrap / Contract owner | 共同对象、状态、错误、迁移与预算接口；公共配置和锁文件 | 产品开发就绪；先最小消费者生命周期，独审冻结 |
| Knowledge owner | 模型/公式/方法/证据种子及版本清单，适配现有 KB | 冻结对象；小批有出处记录与反例，不混写生成语料 |
| Formula owner | 有限解析与确定检查、结果格式 | 冻结公式/检查契约；合法对照和不成立反例 |
| Research owner | 来源适配、步骤执行、受限分析及证据综合 | Budget/Runner/Evidence 共享契约；真实取证与故障恢复 |
| Product UI owner | 现象、公式、研究统一入口及“我的研究” | 先真实接线一条链；保留旧路径适配和手机体验 |
| Integration / QA owner | 干净组合树、任务验收、权限/失败/恢复和质量对照 | 模块初次可连即接线；最终完整产品验收 |
| DevOps owner | 物料、运行配置、预算入口、部署与恢复 | 明确目标/旧数据/凭据/计费边界，精确版本发布 |

这些是职责建议，不表示要同时创建七个 session。PMO 根据文件归属和容量派发；公共 schema、锁文件和组合入口各有唯一 owner。知识和公式可在共享冻结后并行；涉及同一迁移或费用事务的变更不能分开盲合并。

## 9 本轮验证与未验

本轮只读核对固定版本、实际文件、旧 index 的规范化 payload、KB ID 与摘要、NPY 头、LFS 属性及核心调用链。未启动服务、运行模型、调用外部研究/收费供应商、执行迁移或 SSH；没有新增产品代码和测试。两份规划文档应经独立阅读后返修，再由 Product Manager/PMO 确定开发准入。资产细目与清理判据见 [资产审计](ASSET_AUDIT.md)。
