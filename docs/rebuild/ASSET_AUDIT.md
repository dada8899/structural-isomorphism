结论：GitHub main 是代码基线，旧树保留少量潜在独有内容和匹配物料，先分类核价值再整理。主服务、研究资产、生成物和历史记录分开管理；“不在当前主流程”不等于“没有保存价值”。

## 2 Claude 旧树的真实差异

比较读取旧 index 的 blob，而不是把 Git LFS pointer 的文字与真实物料直接比较。普通 blob 使用 payload SHA-256；标准 LFS pointer 使用其声明的 payload SHA-256，并保留文件 mode。该归一只用于定位可能相同内容，不能证明外部 LFS 物料已下载、完整或可运行。

旧 index 有 **2,249 个路径：2,216 普通/可执行文件、33 symlink**。按“先匹配 main，再匹配本地旧 main，再匹配旧 HEAD”的互斥顺序：

| 类别 | 全路径数 | 解释 |
| --- | ---: | --- |
| 与权威 main 相同 | 1,938 | 含 33 个 symlink；仅普通/可执行文件口径为 1,905 |
| 未匹配 main、与本地旧 main 相同 | 130 | 倾向旧实现，但仍需按功能/数据核价值 |
| 前两者不同、与 Claude HEAD 相同 | 39 | 该旧分支自有基线内容，不是未提交新成果的证明 |
| 与三者均不同 | 142 | 潜在独有或混合修改，必须逐项判定 |

142 个不同路径主要分布在 `web` 98、`v4` 9、`.github` 8、`docs` 5、`packages` 5、`scripts` 3，另有根文档、数据和核心包等。只按以上分类不能批准删除，也不能整批合入。下一清理任务应生成精确文件清单，核其消费者、独有行为、生成来源和恢复副本，再分为吸收、保留研究、已替代或不需要。

旧树存在 Git 锁登记；锁文字不证明 writer 当前存活或停写，本轮未检查/终止进程。任何移除须先核 owner、在途命令和实际文件状态。

当前 `.gitattributes` 命中 **74 个路径：56 个 Git blob 是 LFS pointer，18 个是普通 blob**。属性注释明确历史大文件未统一迁移。18 项覆盖结果、结构化 KB、交通/湖泊及 SOC 原始数据等；这是历史保存方式，不据此重写 Git 历史。56 项 pointer 的外部对象完整性仍需逐项 manifest/下载与恢复验证，不能按工作目录存在就放行。

## 5 功能与公开接口接管

主产品静态 HTML 有现象、搜索、分析、报告、账户、分类、发现、论文以及多个工具入口；后端还直接挂载 Phase 类比、时间线和 memo 路由。API 与页面不一定一一对应，目录名也不能证明功能独立。

| 接管对象 | 最少核查 | 退场方式 |
| --- | --- | --- |
| 首页/搜索/结构确认/分析 | query、候选 ID、fingerprint revision、隐私导航和范围拒绝 | 主流程升级，旧路径先适配再退出 |
| mapping/classes/discoveries | 候选 ID/家族、公式、变量映射、证据缺口 | 接入共同模型/公式对象，保留历史快照含义 |
| report/reports/我的研究 | 匿名创建、账户认领、私有列表、分享、回访、旧 payload | 版本适配与数据迁移；不能把旧报告重标为真实研究 |
| methods/lint/stress/diagnose/insights/whitespace/connections | 每个路由的消费者、保存对象、LLM 调用与费用、现有链接 | 有价值能力并入主流程；仅在替代验证后删除重复入口 |
| auth/SSO/privacy | 主账户、Phase 消费者、导出/删除、撤销、cookie/密钥轮换 | 共享安全边界先保持；不能先删 Phase 依赖导致账户失败 |
| pricing/checkout/newsletter/waitlist | 是否 mock、真实用户/订阅数据、邮件/付费行为 | 商业化可暂缓，数据和链接的删除另按清单核实 |
| API/MCP/站点文档 | schema、调用约定、已发布说明、外部消费者 | 兼容或明确退场说明；不能只删导航就认定接口无使用 |

产品负责人决定具体去留与用户反馈方式；本审计提供依赖条件，不替其作重大产品删减。现有公开文档和发布包可能被外部引用，本轮未核访问日志、安装量或实际用户。

## 6 数据、账户与恢复清单

本轮没有 SSH、读取生产行数据或私密配置。下表是必须闭合的接管项，不是已核事实：

| 数据面 | 核查内容 | 恢复与清理前置 |
| --- | --- | --- |
| 账户、token/revocation/deletion epoch、SSO | 实际数据根、schema、主账户关系、仍有效会话 | 一致性备份、隔离恢复及旧新版本凭据语义验证；删除后不可重新接受旧凭据 |
| 报告、回访、收藏、研究资产 | owner、匿名关联、分享、数据来源、实际使用、schema | 原所有权可还原；迁移后保存/重开/导出/删除和分享边界回归 |
| 订阅、waitlist、邮件 outbox | 保留需求、用户承诺、失败重试状态 | 不因“旧账户不需要”连带误删用户仍要求的订阅；测试不向真人乱发信 |
| 新研究任务、证据与预算 | 在途任务、未结算调用、缓存、检查点 | 停止/维护、对账、备份恢复；未知费用不释放，旧代码回退不等于数据库降级 |
| 模型/向量/KB/冻结 Phase 数据 | 完整文件、格式、schema、生成来源、版本与摘要 | 同组物料隔离加载及真实任务验证；不能单独恢复一个文件 |

`report_store.py` 以 SQLite 自增补列并与 history 数据共存；`account_data_registry.py` 提供多资产删除和可选补偿。两者可复用，但补偿不等于跨库原子事务。新数据表必须加入账户导出/删除覆盖。发布脚本有持久数据排除规则，故代码回退不能承担数据恢复。

接管与清理还须核研究在途时的权限竞态：账户删除、撤权或匿名认领变化后，旧任务和迟到回执不得重建已删除的私有资产或继续向无权身份提供内容；费用仅按最小必要收据继续对账，不为结算恢复已删研究正文。该项属于 B1 共享安全探针，不能用静态表结构检查替代。

## 7 清理判据与执行顺序

用户已授权完整接管后删除经验证不需要的内容，不需再次泛化请批。每项清理仍应具备：精确路径/数据选择条件、来源和 owner、用途/消费者、独有内容、替代位置、保留/迁移/删除理由、恢复副本与校验、执行人和验证结果。

1. **先接管。** 代码、物料、用户数据、公开入口、任务和部署拓扑均有可追溯身份；未知项保留理由，不以年代推断无用。
2. **先收敛入口。** 当前状态只留一个入口，历史审计可索引；需求/代码/数据/上线身份各自有权威，避免多份旧状态争夺当前事实。
3. **先做可恢复替代。** 实现适配/迁移、生成必要一致性备份，在隔离目标验证恢复和权限/语义；记录备份位置、owner 与期限。
4. **按小批清单删除。** 临时缓存与已替代生成物优先；资产、旧分支/工作树和业务记录分别核验。仅清理本项目，遵守本机文件流转登记，不把备份原件或项目根作为日常自动删除对象。
5. **验删后结果。** 文件与接口引用闭合，构建/CI/主任务/保存重开/数据导出删除正常；核无独有资产丢失，完成保留/迁移/删除回执。

仅移动到无人知道的位置不算清理完成；保留的研究资产有明确索引和责任。暂不能安全删除的项列入有理由的遗留清单，不伪称全部清空。全仓历史重写、强推和密钥撤销是不同动作；清 Git 历史不能使泄漏密钥失效。
