# 样例一 审核拥堵与排队方法迁移

日期：2026-10-16；关联 F-001/002/003/006/007、A-001。此为任务规格与公开来源核查，不是产品运行或真实业务效果证据。

## 用户输入与澄清

“团队审核一天平均完成 40 项，最近新进约 36 项，积压看起来越来越多。能否从其他领域找到模型和处理办法？我想缩短提交到审核完成的时间。”

系统先核对“40 项”是实际完成量还是估计服务能力、统计期间是否相同、在制品是否含审核中、是否有退回重入、优先级和批量到达。实际输入仅有均值，**不能据此确认 M/M/1 假设或断言已经找到根因**。候选可来自网络分组队列或服务设施，并说明工单反馈和服务时间差异。

## 来源与可支持内容

- 已读取 [MIT《Urban Operations Research》4.4 节](https://web.mit.edu/urban_or_book/www/book/chapter4/4.4.html)：在长期平均量存在、统计边界一致的条件下，系统人数、有效到达率与停留时间满足 Little 关系；排队部分可单独核算，拒绝进入的需求不能计为有效到达。
- 已读取 [MIT 15.760 排队课程讲义](https://ocw.mit.edu/courses/15-760a-operations-management-spring-2002/e6c66bef8fc37c9f4928ea8f816895ab_lecture8_feb22.pdf)，第 6—10 页：服务能力、利用率、流量守恒，以及指数分布条件下拥堵的非线性。

以上是权威教学材料，不是该团队干预有效的实验。首次搜索还定位到 MIT DSpace 讲义，但正文读取返回错误，未用于验收依据。

## 正常结果样貌

先建议用同一边界统计入流、出流、在制品和停留时间，辨别是否持续净积压。Little 关系 `L=λW` 是核对关系，不单独给出因果或最优处理方案。

作为**声明额外假设的演算**，若工单独立泊松到达、单审核者服务时间独立指数分布、无优先级/重入、稳定且有效到达率 `λ=36/工作日`、能力 `μ=40/工作日`，则：

```text
ρ = λ/μ = 0.9
W = 1/(μ-λ) = 0.25 工作日（排队加服务）
Wq = λ/[μ(μ-λ)] = 0.225 工作日（仅排队）
L = λW = 9 项（在制品）
```

这些数字由该 M/M/1 条件模型推得，不是当前团队的实测等待时间。迁移提议可比较减少无效入流、减少返工或增加有效能力；保留质量、成本和优先级约束，不把“提高利用率”直接作为缩短等待的方案。若将能力假设改为 45/工作日，同一模型预测 `W=1/9 工作日`；实际收益需试验。

本轮已用 Python 对上述简单算术交叉核对，结果一致；未运行排队仿真或产品求解器。

最小验证：先取得逐项提交、开始、完成和返工时间，检查边界与长期净流量；选择一个可回退的流程干预，与同类任务的基线比较周期、返工和审核质量。服务分布或独立性不成立时改用经验事件重放/受控模拟，不输出 M/M/1 精确承诺。

## 反例与验收

| 输入或检查 | 预期 | 失败判据 |
| --- | --- | --- |
| 上述明确条件和单位 | 计算与单位一致，区分 W/Wq；方法与假设可查看 | 将排队时间和总周期混用，或把演算当实测 |
| `λ=42, μ=40` 且无限队列 | 拒绝稳态均值公式，解释积压风险 | 给负等待时间或稳定结论 |
| “每天平均 36 项，但每周一一次批量到达” | Little 可作边界核对，M/M/1 条件待核 | 仅凭均值给精确实时预测 |
| “审核越来越慢就是大家不努力” | 保留竞争解释与所需观测 | 将用户归因当已证实机制 |
| 保存、改 λ、重开旧报告 | 新修订与旧条件分开 | 旧报告数字被静默覆盖 |
