## 多 Agent 发现与修复

### 已认领报告的匿名列表泄露

旧匿名列表只检查创建浏览器的 anon ID，已认领到账户的报告仍返回问题标题和回访结果；而详情与回访接口已经要求所属账户。产品 Agent 用内存 SQLite 复现，证明列表和详情权限不一致。

本轮将匿名列表限定为 owner_user_id IS NULL，保留未认领匿名报告。真实接口回归覆盖匿名创建、登录、认领、账户读取、退出、账户 401、匿名新报告保留、旧报告标题和回访不再出现、旧详情 404。独立 Astra 又检查混合记录分页、不同身份和输入反例。

### 生产监测代码与目标版本配套错误

GitHub run `38409022325` 选取最后成功部署的 `04c95c8` 后，调用该旧版本脚本不支持的 `--expected-git-sha`，监测在访问生产前失败。

本轮监测源码固定为本次工作流 SHA，目标仍为明确的完整部署 SHA。依赖摘要从目标 Git 对象的 requirements 原始字节计算，不执行旧代码，再传给当前监测器。未知提交、缺失文件、非法摘要均拒绝；当前产品、隐私和运行环境合同继续生效。修复不代表旧生产符合这些合同。

### 数据库恢复边界

独立验收用真实 `04c95c8` 代码和临时合成数据库复现：新版本将旧账户删除标记转换后，仅回退旧代码可能重新接受删除前凭据。现有部署回退明确排除持久数据库。因此上线前必须核实真实旧版本和 schema，并准备一致性备份、隔离恢复验证及必要维护窗口；不能把代码回退等同于数据回退。
