# Release notes — v0.1.1 (2026-05-24)

This is a coordinated **docs + CI** patch release across the three PyPI
packages extracted from the [structural-isomorphism](https://github.com/dada8899/structural-isomorphism)
project. No behavioural changes. Public APIs are byte-compatible with
`0.1.0`.

| Package | 0.1.0 → 0.1.1 | PyPI |
|---|---|---|
| `guarded-llm` | docs + CI | <https://pypi.org/p/guarded-llm> |
| `soc-pipeline` | docs + CI | <https://pypi.org/p/soc-pipeline> |
| `cross-judge` | docs + CI | <https://pypi.org/p/cross-judge> |

## What's new

### Documentation

Every package now ships a consistent three-file `docs/` set inside the
sdist:

- `docs/quickstart.md` — three-line install + minimal end-to-end example.
- `docs/api-reference.md` — full public API surface, including return-type
  shapes and exception hierarchies.
- `docs/changelog.md` — pointer to the package's top-level `CHANGELOG.md`.

Each package also ships a root `CHANGELOG.md` in
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) format with
`[0.1.0]` and `[0.1.1]` sections plus GitHub-compare diff links.

### CI / Release infrastructure

Two new repo-level workflows under `.github/workflows/`:

- **`ci-packages.yml`** — Per-package CI matrix.
  - Triggers: PR + push to `main` (path-filtered to `packages/**`),
    plus `workflow_dispatch`.
  - Matrix: Python `3.10` / `3.11` / `3.12` / `3.13` on
    `ubuntu-latest` and `macos-latest`.
  - Per cell: `pip install -e ".[dev]"` → `pytest` → `python -m build`
    → `twine check --strict`.
  - Uploads sdist + wheel as 14-day artifacts on the canonical
    Linux × py3.11 leg for each package.
  - Concurrency: in-flight runs cancelled per ref.

- **`release-packages.yml`** — Tag-driven publish.
  - Triggers on tags matching `guarded-llm-v*`, `soc-pipeline-v*`,
    or `cross-judge-v*`; plus `workflow_dispatch` with a `dry_run` flag.
  - Resolves the target package from the tag prefix.
  - Verifies the tag version matches `pyproject.toml`'s `version`
    before building (catches accidental mismatches).
  - Builds sdist + wheel, runs `twine check --strict`, publishes to
    PyPI via `PYPI_API_TOKEN` if that secret is configured.
  - **Degrades safely when the secret is absent**: the workflow can be
    merged now; the upload step emits a warning + Step Summary, no
    failure. Add the `PYPI_API_TOKEN` secret in
    *Settings → Secrets and variables → Actions* whenever you are ready
    to flip on auto-publish.
  - Artifacts uploaded with 90-day retention for provenance.

The existing `sanity.yml` (the workflow gated by main-branch protection)
has been extended to also run the per-package unit tests and the
`web/backend` pytest baseline (781 tests as of `2026-05-24`), so a green
`sanity` check now covers all three legs.

### Versioning hygiene

- `pyproject.toml` `version` bumped: `0.1.0` → `0.1.1` in all three
  packages.
- `__version__` symbol bumped to match in all three top-level
  `__init__.py` files.
- `cross-judge` gains a `MANIFEST.in` so `CHANGELOG.md` and `docs/` are
  picked up into the sdist (setuptools backend).

## Breaking changes

**None.** This release is wire- and import-compatible with `0.1.0`. The
public API surface — `guardrailed_llm_call` / `GuardedLLM`,
`fit_clauset_powerlaw` / `bootstrap_ci` / `fit_b_value`, `Critic` /
`Ensemble` / `Verdict` — is unchanged.

```bash

```

No code changes required.

## How releases work now (after this patch)

Once `PYPI_API_TOKEN` is added as a repository secret, a tag push will
auto-publish that single package:

```bash
# bump packages/guarded-llm/pyproject.toml + src/.../__init__.py to 0.1.2
git commit -am "release(guarded-llm): 0.1.2"
git tag guarded-llm-v0.1.2
git push origin guarded-llm-v0.1.2
# release-packages.yml builds, twine-checks --strict, and uploads to PyPI
```

Without the secret, the same tag push still runs build + twine check and
uploads dist artifacts to the run for manual download — useful for the
PRE-secret window we're in right now.
